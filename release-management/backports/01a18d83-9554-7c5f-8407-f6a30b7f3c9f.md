## Justification (public)

Adds two Keystone roles: a project reader (`rgw_keystone_accepted_project_reader_roles`), read-only by default, and an implicit-deny role (`rgw_keystone_implicit_deny_roles`), no access by default. Both can be granted more through bucket policy using `keystone:userid` or `keystone:role`.

## Justification (internal)

Customer roadmap feature, mirroring Swift's `project_reader_roles`.

## Risk notes

**blast: availability** — off by default, but it changes how permissions are computed for every Keystone user. A mistake could remove access; no data is at risk.

**conflict: substantive** — tentacle lacks some newer upstream code, so STS, SNS topics and the new unit test needed small manual adaptations. Merged code matches upstream otherwise.

**coverage: strong** — unit tests and live tests against RGW and Keystone pass. They cover read-only and no-access defaults, policy overrides by `keystone:userid` and `keystone:role`, `Deny` precedence and cross-project isolation.

## Behavior change

Two new options, empty by default:

- `rgw keystone accepted project reader roles` — user is read-only within its project.
- `rgw keystone implicit deny roles` — user has no access without an explicit policy grant.

The most permissive accepted role wins (`member` or `admin` gives full control). A bucket policy naming the user or role can grant more, for that bucket only. Bucket creation and STS `AssumeRole` are always refused for these users.

## Upgrade notes

None. Both options default to empty.
