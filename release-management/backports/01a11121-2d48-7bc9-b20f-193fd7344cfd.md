## Justification (public)

Add OpenStack Keystone authentication scope information to RGW operations logs.
It enables audit trails for multi-tenant and compliance-sensitive environments,
by adding the keystone_scope field (project, user, domain, roles, application
credentials) to RGW ops logs.

## Justification (internal)

Keystone scope logging - customer ticket cobaltcore-dev/cloud-storage#335;
upstream PR #66111 (merged to main).

## Risk notes

Scope logging with rgw_keystone_scope_include_user=true writes human-readable
usernames to ops logs, which may have GDPR / privacy implications.

The cherry-pick drops upstream 47166556c5b commit. It is not in tentacle and
the upstream commit 5d6d51eb556 was written on top of it.
rgw::auth::RemoteApplier::AuthInfo therefore diverges from upstream main by one
positional parameter. Future backports touching those auth paths will conflict
there and must be resolved by hand.

## Behavior change

Keystone scope (project, domain, roles) appears in RGW ops logs. This feature
is OFF by default.

The top-level ops-log user field is not populated with the Keystone username.
That identity is available only as keystone_scope.user, gated on
rgw_keystone_scope_include_user=true. This differs from upstream main and from
the squid backport 01a06155.

## Upgrade notes

rgw_keystone_scope_enabled (default: false) - enable Keystone scope in the ops
  log
rgw_keystone_scope_include_roles (default: true) - include role names into the
  ops log
rgw_keystone_scope_include_user (default: false) - adds human-readable names
  for project_name, domain names, user_name and app_cred_name. Leave false
  unless the GDPR implications above are accepted.
